# auth-postgres

Адаптер хранения: реализации портов `auth-core` на `sqlx`/Postgres.

## Транзакции

`PgUnitOfWork::begin` открывает `PgTx` (обёртка над `sqlx::Transaction`).
Пишущие методы репозиториев принимают её как `&mut dyn Tx` и достают соединение
через downcast; транзакция, созданная другим адаптером, даёт `Internal`. `PgTx`,
сброшенная без `commit`, откатывается.

## Схема

`users`, `roles`, `permissions`, `role_permissions`, `user_roles`, `sessions`,
`app_settings`, `audit_events` — см. `migrations/`. Миграции гоняются через
`sqlx::migrate!` (`auth_postgres::migrate(&pool)`); `auth-server` применяет их
при старте. Выпущенные миграции не меняются — только добавляются новые.

Детали схемы:

- `user_roles.scope` хранит `''` вместо `NULL` для глобальных ролей: в Postgres
  `NULL` в уникальном индексе не конфликтует сам с собой, а повторное назначение
  одной и той же глобальной роли должно давать `Conflict`.
- `audit_events.scope` — `NULL` для глобальных событий (уникальности там нет), а
  у `actor_id` нет внешнего ключа: записи о действиях удалённого пользователя
  остаются.
- `audit_events` только дописывается: `UPDATE`, `DELETE` и `TRUNCATE` запрещены
  триггером. Чистить старые записи — отдельной миграцией, явно отключающей триггер.

## Функции и триггеры

- `register_permission(code, description)` — так сторонние сервисы добавляют
  свои права из своих миграций. Проверяет код по тому же правилу, что и
  `PermissionCode`, идемпотентна (повторный вызов обновляет описание).
- `permissions_grant_admin` — каждое новое право автоматически выдаётся `admin`.

## Блокировки

- `RoleRepository::lock` — `SELECT ... FOR UPDATE` на строке роли, затем чтение
  её прав уже под блокировкой. Параллельные операции над той же ролью ждут.
- `admin_guard` — блокирует строку роли `admin` и проверяет, что после снятия
  роли, деактивации или удаления активный админ остался.
- `PgSessionRepository::rotate` — `SELECT ... FOR UPDATE`: параллельный refresh
  одним и тем же токеном не может выдать два валидных результата.
- `SetupRepository::create_first_admin` — блокирует строку `app_settings`: из
  параллельных запросов настройки проходит ровно один. Сам открывает и коммитит
  транзакцию и внутри неё пишет `setup.complete` в журнал аудита.

## Заметки

- `sqlx 0.9` требует `&'static str` для SQL (`SqlSafeStr`): все запросы —
  литералы или `concat!`, без `format!`.
- Детали аудита — `jsonb`-объект строк, пишется через
  `jsonb_object(keys, values)`, поэтому адаптеру не нужен `serde_json`.

## Тесты

Интеграционные, на `testcontainers` — поднимают настоящий Postgres в Docker:

```powershell
cargo test -p auth-postgres   # нужен запущенный Docker
```

Покрывают откат при drop и при ошибках, защиту последнего админа при
параллельных запросах, блокировку ролей, журнал аудита (откат, фильтры, запрет
изменений) и SQL-функции.
