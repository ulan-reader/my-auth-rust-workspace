# auth-postgres

Сақтау адаптері: `auth-core` порттарының `sqlx`/Postgres-тегі іске асырылуы.

## Транзакциялар

`PgUnitOfWork::begin` `PgTx` ашады (`sqlx::Transaction` орамы). Репозиторийлердің
жазатын әдістері оны `&mut dyn Tx` ретінде қабылдайды және қосылысты downcast
арқылы алады; басқа адаптер жасаған транзакция `Internal` береді. `commit`
жасалмай тасталған `PgTx` кері қайтарылады.

## Схема

`users`, `roles`, `permissions`, `role_permissions`, `user_roles`, `sessions`,
`app_settings`, `audit_events` — `migrations/` қараңыз. Миграциялар
`sqlx::migrate!` (`auth_postgres::migrate(&pool)`) арқылы орындалады;
`auth-server` оларды іске қосылғанда қолданады. Шығарылған миграциялар
өзгертілмейді — тек жаңалары қосылады.

Схема мәліметтері:

- `user_roles.scope` жаһандық рөлдер үшін `NULL` орнына `''` сақтайды:
  Postgres-те бірегей индекстегі `NULL` өзімен-өзі қақтығыспайды, ал бір
  жаһандық рөлді қайта тағайындау `Conflict` беруі керек.
- `audit_events.scope` жаһандық оқиғалар үшін `NULL` (онда бірегейлік жоқ), ал
  `actor_id`-де сыртқы кілт жоқ: жойылған пайдаланушының әрекеттері туралы
  жазбалар сақталады.
- `audit_events` тек толықтырылады: `UPDATE`, `DELETE` және `TRUNCATE`
  триггермен тыйым салынған. Ескі жазбаларды тазалау — триггерді анық
  өшіретін бөлек миграция арқылы.

## Функциялар мен триггерлер

- `register_permission(code, description)` — басқа сервистер өз рұқсаттарын
  өз миграцияларынан осылай қосады. Кодты `PermissionCode`-пен бірдей ереже
  бойынша тексереді, идемпотентті (қайта шақыру сипаттаманы жаңартады).
- `permissions_grant_admin` — әр жаңа рұқсат `admin` рөліне автоматты түрде беріледі.

## Бұғаттаулар

- `RoleRepository::lock` — рөл жолына `SELECT ... FOR UPDATE`, содан кейін
  оның рұқсаттарын бұғаттау астында оқу. Сол рөлге қатар операциялар күтеді.
- `admin_guard` — `admin` рөлінің жолын бұғаттайды және рөлді алып тастау,
  өшіру немесе жоюдан кейін белсенді әкімші қалғанын тексереді.
- `PgSessionRepository::rotate` — `SELECT ... FOR UPDATE`: бір токенмен қатар
  жасалған refresh екі жарамды нәтиже бере алмайды.
- `SetupRepository::create_first_admin` — `app_settings` жолын бұғаттайды:
  қатар келген баптау сұраныстарының дәл біреуі ғана өтеді. Транзакцияны өзі
  ашып, өзі commit жасайды және оның ішінде аудит журналына `setup.complete`
  жазады.

## Ескертпелер

- `sqlx 0.9` SQL үшін `&'static str` талап етеді (`SqlSafeStr`): барлық
  сұраныс — литерал немесе `concat!`, `format!` жоқ.
- Аудит мәліметтері — жолдардан тұратын `jsonb`-объект,
  `jsonb_object(keys, values)` арқылы жазылады, сондықтан адаптерге `serde_json`
  керек емес.

## Тесттер

Интеграциялық, `testcontainers` негізінде — Docker-де нақты Postgres көтереді:

```powershell
cargo test -p auth-postgres   # Docker іске қосулы болуы керек
```

Drop және қате кезіндегі кері қайтаруды, қатар сұраныстар кезінде соңғы
әкімшіні қорғауды, рөлдерді бұғаттауды, аудит журналын (кері қайтару, сүзгілер,
өзгертуге тыйым) және SQL-функцияларды қамтиды.
